# Project: layout, environments, commits, docs, tests

## Layout

The workspace layout is the Fluig Studio one, which `fluigctl` also reads:

```
datasets/<processo em português>/   datasets/Utils/
events/            global events
forms/form<Nome>/
mechanisms/
reports/
templates_email/
wcm/widget/<code>/   wcm/layout/<code>/
workflow/diagrams/   workflow/scripts/   workflow/.resources/
docs/   tests/       (when the project has them)
```

- **One repository per client, one branch per process.** Branches are named
  `<processo>-<id da tarefa no ClickUp>` (`solicitacao-compras-86ad3n63q`). Git
  worktrees, one folder per branch, let several processes stay open side by side.
- **Every branch carries all the processes,** so a change to a shared dataset
  (`Utils/`, `aprovação de movimento/`) has to reach the other branches. Note it
  in the commit and merge it on.
- **Never commit `forms/NNN - formX/` copies** made by a Studio export. They
  diverge from the real form.

## Environments

- **Detect the environment from the server URL**:
  `String(fluigAPI.getPageService().getServerURL())`.
- **A homolog server often answers on several URLs** (IP, internal hostname,
  public hostname). List all of them.
  - Each copy of `isDev()` that checked only one URL broke in the environment it
    missed.
  - The same list lives in the front-end (`useEnv.ts`) and must change together.
  - Log a miss: `log.info("isDev=false para serverURL=" + serverUrl)`.
- **Ids that differ per environment** (GED root folder, form folders) are chosen
  next to each other at the top: `isDev() ? "615" : "27794"`.
- **Production is published by the human** (see `fluig-deploy`).

## Commits

Conventional Commits, in Portuguese, lowercase, mostly without accents:

```
feat(reembolso): alcada real pela FLUIG.003 e recusa de aprovador sem usuario
fix(ged): getSubFolders nao devolve documento, troca por getSubFoldersOnDemand
perf(reembolso): no maximo 4 consultas ao RM de uma vez
chore(medicao-contratos): diagrama reexportado pelo Studio
```

- **Types:** `feat`, `fix`, `perf`, `refactor`, `docs`, `test`, `chore`,
  `security`.
- **The scope is the process or feature** (`medicao-contratos`, `reembolso`,
  `portal-fornecedor`, `ged`, `utils`), not the artifact type.
- **References to the client's checklist** go in parentheses: `(item 9)`.
- **The body explains why, in `-` bullets.**
- **Never commit with the subject `deploy`, `.` or `y`.**

## Docs (`docs/`)

Documents are in Portuguese and dated. They cite commit hashes and the request
numbers involved. Mark facts measured on the server, as opposed to read in the
repo, with 🔴.

| Doc | Purpose |
|---|---|
| `especificacao-diagrama-<processo>.md` | step-by-step modelling script for the diagram (see workflow.md) |
| `matriz-visibilidade-<processo>.md` | block/field × activity matrix, generated by running `displayFields`/`main.js` for each activity |
| `consultas-rm-<processo>.md` + `sql-rm-NN-*.sql` | each RM sentence: dataset, `PAR_*`, cardinality, consumer, columns, sample row |
| `checklist-publicacao-<processo>.md` | what differs between the repo and HML, grouped by severity, as `- [ ]` items |
| `checklist-deploy-producao-<processo>.md` | ordered runbook: RM → Fluig configuration → sentences → datasets → form → process → widget → switches → smoke test; each `[x]` carries date and who did it |
| `estado-<processo>.md` | inventory of what is done and what is missing ("não é planejamento: é inventário") |
| `pendencias-<processo>.md` | short living list: before production, to confirm with the client, in the RM, in HML |

## Tests

The Medição branch has the model, in `tests/`.

**Form suites (`*.casos.js`)** run in headless Chrome against the real form
HTML:
- A script assembles the page from the form, jQuery and the form's JS.
- Stubs replace `DatasetFactory` / `getDatasetAsync`: `respostasDeDataset["dsX"] = [...]`.
- Helpers:
  - `estarNaEtapa(atividade, modo)`
  - `montarLinha(tabela, i, valores)` (child rows `___N`)
  - `ok(nome, cond, detalhe)`, which prints `PASSOU` / `FALHOU`

**Server suites (`*.node.js`)** load datasets, service tasks, `validateForm` and
`displayFields` with `vm.runInContext`, with fake `hAPI`, `DatasetFactory`,
`ConstraintType` and cards. Each file's header names the bug it covers.

**A `rodar.sh`** runs every suite and exits 1 on failure. Run it before every
commit.

**End-to-end against HML (`tests/e2e-hml/`):**
- A small Chrome DevTools Protocol driver attaches to a Chrome already logged in
  (`:9222`), so the tests hold no credentials.
- Dataset and card helpers are injected into the page.
- Scenario scripts cover the happy path, rejection, adjustments and two levels
  of approval.
- RM queries go through the read-only SQL console dataset.
- Prerequisites (stubs on in HML, `MODO_TESTE`) and the leftovers each run
  creates (real requests, RM movements) are written down in the README.

## WCM widgets with a modern front-end

- **The WCM widget is a thin shell:**
  - `application.info` and `jboss-web.xml` (`context-root=/<code>`);
  - a `view.ftl` that only loads the bundle (`<script type="module" src="/<code>/resources/js/app-vue/index.js">`
    plus `<div id="app">`);
  - a `SuperWidget` wrapped in `if (typeof SuperWidget !== 'undefined')` for
    layouts without the WCM header.
- **The app lives in `vue_widgets/<nome>/`** (Vue 3 + Vite + TS). Vite builds
  into the widget's `resources/js/app-vue` with fixed file names.
- **Don't commit the bundle.** Rebuild it before publishing.
- **Stamp the build.** Inject commit, dirty flag and time, and print them to the
  console. That is how you check that the server runs what you built.
- **External access with no Fluig login uses a token (magic link):**
  - the token is encrypted on the server from the identifiers;
  - it travels in the query string, URL-encoded;
  - it is valid only in the activities that expect the outside party;
  - one dataset resolves it.
- **The anonymous page is not exposed to the internet until it has TLS.**
- **An application code used in homolog cannot be reused.** Pick a new one
  instead of fighting the old registration.
