# Preview local — fundação local-04

A fundação usa controle tokenizado em `127.0.0.1` e formulário em iframe opaco (`allow-scripts allow-forms allow-modals`, sem `allow-same-origin`). O token, alias e credenciais existem somente no controle; o frame recebe apenas um nonce aleatório de ciclo. A CSP do controle é `default-src 'none'; frame-src 'self'; script-src 'unsafe-inline'; connect-src 'self'` — o `connect-src 'self'` existe porque o controle abre um canal SSE same-origin (`/events/<token>`) para recarregar o frame quando o formulário é salvo. O frame mantém `connect-src 'none'` e segue embutível somente pelo loopback local.

O controle compara `event.source` com `iframe.contentWindow`, confere handshake exato `v=1/type=hello/nonce`, e só então transfere um `MessagePort` novo. Mensagens posteriores são estritas, limitadas e têm IDs persistentes contra replay; reload/close limpa a sessão. O núcleo não expõe API de controle ou escrita para o frame, nem proxy ou fetch remoto: além do controle e do frame, ele serve assets do Style Guide a partir do cache local em `/style-guide/*` e `/portal/resources/*`, mais `/state/<token>` (status JSON, `cache-control: no-store`) e `/events/<token>` (SSE de reload). O cache é populado pelo `form bootstrap`; o `FLUIGC` é carregado do `fluig-style-guide.min.js` do cache quando presente, e componentes que dependem do servidor degradam com diagnóstico. Com `form open --server <alias>`, o `DatasetFactory.getDataset(...)` do frame chega ao servidor real pela ponte do controle (`POST /dataset/<token>`); sem `--server`, a chamada devolve erro explícito e nenhum dado inventado. Datasets não são cacheados e podem ter efeito no servidor — use datasets de leitura. Eventos de servidor não são executados.

A pasta é canonicalizada antes de escolher HTML; o HTML escolhido também é canonicalizado e contido na raiz. Assets exigem arquivo regular dentro da raiz canônica; traversal literal/codificado, absoluto, NUL e symlinks escapando são recusados. Scripts do formulário **não** são removidos: os scripts locais selecionados são confiados para renderizar/interagir e podem substituir ou navegar seu próprio frame. Isso é risco residual inerente a executar JS autoral; o sandbox ainda não permite navegar o topo, nem dá acesso ao pai, token de controle ou credenciais. A CSP do frame usa `connect-src 'none'`, que bloqueia requisições iniciadas por script (`fetch`, `XMLHttpRequest`, WebSocket, EventSource), e `form-action 'none'`, que bloqueia a submissão de formulários. Isso **não** garante ausência total de tráfego: a navegação do próprio iframe (mudar `location`, meta refresh ou um link que navega o frame) ainda pode disparar uma requisição remota, porque navegação não é regida por `connect-src`/`form-action`. O frame continua opaco (sem `allow-same-origin`): não acessa parent/top, token de controle, alias, cookies nem credenciais do backend. Os assets do cache são servidos com a mesma disciplina de traversal dos assets locais, e o `connect-src 'self'` do controle serve apenas ao SSE local.

## Shim injetado no frame

Antes dos scripts do próprio formulário, o frame recebe um shim (`scriptDaApi`) que simula o ambiente Fluig: um contexto SIMULADO (`WKNumState`, `WKUser`, `WKMode` e, quando informados, `WKNumProces`/`WKCompany`) derivado de `--modo`/`--atividade`/`--usuario`; a API do formulário (`getValue`/`setValue`, `form.getValue`/`setValue`/`getFormMode`, `getAtividade`/`getMode`/`getUser`); e tabelas pai-filho (`wdkAddChild`/`fnWdkRemoveChild`, sufixo `___N`, linha modelo escondida, `form.getChildrenIndexes`). Há ainda uma ponte FLUIGC: `__fluigPreview.calendar`/`__fluigPreview.select` chamam o `FLUIGC` real do `fluig-style-guide.min.js` servido do cache; se o `FLUIGC` faltar, o componente não existir ou estourar, a ponte devolve `null` e registra um diagnóstico, sem lançar. O shim nunca faz rede. Há também a ponte de datasets: `DatasetFactory.createConstraint`/`ConstraintType` e `DatasetFactory.getDataset` enfileiram até `__fluigPreview.conectar(port)` e tramitam pelo `MessagePort` do controle, virando `POST /dataset/<token>` no processo local; com `--server` esse route consulta o servidor real, sem `--server` devolve erro explícito. O contexto é simulado, não vem de um processo real; eventos de servidor (`displayFields`/`enableFields`/`validateForm`) NÃO são executados, e componentes que dependem do servidor degradam com diagnóstico.

O cache de Style Guide deixou de ser fatia futura: virou o `form bootstrap`, já implementado e validado contra o `fluig-localdev`. Ele resolve cada asset por uma lista ordenada de candidatos — no localdev o CSS principal veio do caminho `-flat` (`/style-guide/css/fluig-style-guide-flat.min.css`), o cache ficou com 182 arquivos e 2 assets decorativos referenciados pelo CSS foram registrados como ignorados, sem abortar o bootstrap. A demonstração offline com esse cache real foi executada, sem navegador. A fatia futura restante são os eventos de servidor. Same-origin foi rejeitado porque daria ao script do formulário capacidade ambiente sobre o controle local.
